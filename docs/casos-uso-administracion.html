Acceso y Pestañas

Valida que el panel muestre solo lo que el usuario puede administrar.

CU-ADM-01

Entrar al panel de administración

Pasos

  1. Iniciar sesión con usuario administrador.
  2. Abrir Configuración/Administración desde el menú.

Resultado esperado

  • Carga el panel sin errores.
  • Muestra encabezado de administración.
  • Las pestañas visibles coinciden con permisos del usuario.
CU-ADM-02

Ocultar pestañas sin permiso

Pasos

  1. Entrar con usuario con permisos limitados.
  2. Revisar Usuarios, Roles, Seguridad y Apariencia.

Resultado esperado

  • Solo aparecen pestañas autorizadas.
  • No hay forma visual de acceder a secciones restringidas.
  • Si no tiene ningún permiso, muestra pantalla sin permisos.
CU-ADM-03

Cambio de pestañas

Pasos

  1. Cambiar entre Usuarios, Roles, Seguridad y Apariencia.
  2. Volver a la primera pestaña.

Resultado esperado

  • Cada pestaña carga su contenido correcto.
  • No se mezclan listas ni formularios.
  • No aparecen errores al cambiar rápido.
CU-ADM-04

Acceso directo por URL

Pasos

  1. Con usuario limitado, intentar abrir la URL del panel.
  2. Probar con sesión cerrada.

Resultado esperado

  • Sin sesión redirige a login.
  • Sin permisos no muestra información administrativa.
  • No hay datos sensibles en pantalla.

Usuarios e Invitaciones

Prueba altas de acceso, asignación de roles y estados de usuario.

CU-ADM-05

Listar usuarios del sistema

Pasos

  1. Abrir pestaña Usuarios.
  2. Revisar lista de usuarios.

Resultado esperado

  • Muestra nombre, correo, UID, estado y roles asignados.
  • Los usuarios inactivos/bloqueados se distinguen.
  • No muestra contraseñas ni datos privados innecesarios.
CU-ADM-06

Crear invitación

Pasos

  1. Dar clic en Nueva invitación.
  2. Capturar correo válido.
  3. Seleccionar roles iniciales.
  4. Crear invitación.

Resultado esperado

  • La invitación queda en pendientes.
  • Se guarda con correo normalizado.
  • Registra movimiento en Bitácora.
CU-ADM-07

Validar invitación duplicada o inválida

Pasos

  1. Intentar invitar con correo inválido.
  2. Intentar crear otra invitación pendiente al mismo correo.

Resultado esperado

  • No permite correo inválido.
  • No duplica invitaciones pendientes.
  • Muestra mensaje claro al administrador.
CU-ADM-08

Primer acceso con invitación

Pasos

  1. Entrar a Primer acceso con correo invitado.
  2. Crear contraseña.
  3. Iniciar sesión.

Resultado esperado

  • Solo acepta invitaciones pendientes.
  • El perfil se crea con roles iniciales.
  • La invitación queda usada y no reutilizable.
CU-ADM-09

Cancelar invitación

Pasos

  1. Crear una invitación de prueba.
  2. Cancelar la invitación.
  3. Intentar usarla en Primer acceso.

Resultado esperado

  • Desaparece o cambia de estado en pendientes.
  • No permite registrar usuario con invitación cancelada.
  • Queda registro en Bitácora.
CU-ADM-10

Asignar roles a usuario

Pasos

  1. Seleccionar un usuario.
  2. Abrir Asignar roles.
  3. Marcar uno o varios roles activos.
  4. Guardar.

Resultado esperado

  • Los roles quedan visibles en la ficha del usuario.
  • Los permisos efectivos se recalculan.
  • El usuario ve el menú según sus nuevos permisos.
CU-ADM-11

Cambiar estado de usuario

Pasos

  1. Desactivar un usuario de prueba.
  2. Intentar iniciar sesión con ese usuario.
  3. Bloquearlo y repetir.

Resultado esperado

  • El estado cambia correctamente.
  • Usuario inactivo o bloqueado no puede operar.
  • El cambio queda en Bitácora.
CU-ADM-12

Eliminar visualmente usuario

Pasos

  1. Usar un usuario de prueba.
  2. Dar clic en Eliminar.
  3. Confirmar si el sistema lo solicita.

Resultado esperado

  • No elimina datos clínicos ni movimientos históricos.
  • El acceso queda removido o marcado según diseño.
  • La acción queda auditada.

Roles y Permisos

Valida configuración de permisos sin romper accesos existentes.

CU-ADM-13

Listar roles configurados

Pasos

  1. Abrir pestaña Roles.
  2. Revisar roles activos e inactivos.

Resultado esperado

  • Muestra nombre, descripción, estado y permisos.
  • Los roles base no se pierden.
  • La pantalla carga aunque no haya roles personalizados.
CU-ADM-14

Crear rol nuevo

Pasos

  1. Crear rol de prueba.
  2. Asignar permisos por grupo.
  3. Guardar.

Resultado esperado

  • El rol aparece en la lista.
  • Los permisos seleccionados se guardan completos.
  • Queda disponible para asignar a usuarios.
CU-ADM-15

Editar permisos de rol

Pasos

  1. Editar rol de prueba.
  2. Agregar y quitar permisos.
  3. Guardar y recargar.

Resultado esperado

  • Los cambios persisten.
  • No duplica permisos.
  • Los usuarios con ese rol reciben permisos actualizados al recalcular.
CU-ADM-16

Desactivar rol

Pasos

  1. Desactivar un rol de prueba.
  2. Intentar asignarlo a un usuario.

Resultado esperado

  • El rol cambia de estado.
  • No aparece como opción activa para nuevas asignaciones.
  • No rompe usuarios existentes.
CU-ADM-17

Eliminar rol de prueba

Pasos

  1. Crear rol temporal.
  2. Eliminarlo.
  3. Revisar usuarios y bitácora.

Resultado esperado

  • El rol desaparece o queda archivado según diseño.
  • No quedan referencias rotas visibles.
  • La eliminación queda auditada.
CU-ADM-18

Permisos efectivos en menú

Pasos

  1. Crear rol con permisos limitados.
  2. Asignarlo a usuario de prueba.
  3. Entrar con ese usuario.

Resultado esperado

  • El menú solo muestra módulos permitidos.
  • Las acciones internas también respetan permisos.
  • No basta ocultar botones: Firestore debe bloquear escrituras no autorizadas.

Seguridad de Sesiones

Revisa dispositivos activos, sesiones remotas y trazabilidad.

CU-ADM-19

Ver resumen de sesiones

Pasos

  1. Abrir pestaña Seguridad.
  2. Revisar KPIs de sesiones.

Resultado esperado

  • Muestra sesiones activas, usuarios conectados, actividad reciente y sesiones por revisar.
  • Los contadores coinciden con la lista.
  • No muestra información imposible como IP exacta si no existe backend.
CU-ADM-20

Listar sesiones de usuarios

Pasos

  1. Iniciar sesión en dos navegadores o dispositivos.
  2. Revisar lista de sesiones.

Resultado esperado

  • Distingue este navegador de sesiones remotas.
  • Muestra usuario, dispositivo, navegador, sistema y última actividad.
  • Marca sesiones recientes o por revisar.
CU-ADM-21

Buscar sesiones

Pasos

  1. Buscar por nombre, correo, navegador o sistema.
  2. Limpiar búsqueda.

Resultado esperado

  • Filtra sesiones correctamente.
  • El estado vacío es claro.
  • Al limpiar vuelve la lista completa permitida.
CU-ADM-22

Cerrar sesión remota

Pasos

  1. Seleccionar una sesión remota.
  2. Dar clic en Cerrar sesión.
  3. Confirmar alerta.

Resultado esperado

  • No permite cerrar el navegador actual desde esa acción.
  • La sesión remota se cierra.
  • Queda registro en Bitácora.
CU-ADM-23

Cerrar sesiones remotas en bloque

Pasos

  1. Tener más de una sesión remota.
  2. Usar Cerrar sesiones remotas.
  3. Confirmar.

Resultado esperado

  • Cierra solo sesiones remotas.
  • Conserva la sesión actual.
  • Audita el cierre masivo.
CU-ADM-24

Permisos de revocación

Pasos

  1. Entrar con usuario sin permiso de revocar sesiones ajenas.
  2. Intentar cerrar sesión de otro usuario.

Resultado esperado

  • El botón está oculto o deshabilitado.
  • Firestore no permite la acción no autorizada.
  • No se cierran sesiones ajenas.

Apariencia y Robustez

Valida tema visual, persistencia por perfil y estabilidad del panel.

CU-ADM-25

Cambiar a modo oscuro

Pasos

  1. Abrir Apariencia.
  2. Seleccionar Modo oscuro.
  3. Recorrer pantallas principales.

Resultado esperado

  • El tema cambia sin recargar.
  • El badge muestra Oscuro/Activo.
  • Textos, tablas y modales siguen legibles.
CU-ADM-26

Cambiar a modo normal

Pasos

  1. Desde modo oscuro, seleccionar Modo normal.
  2. Revisar que el sistema vuelva a claro.

Resultado esperado

  • El tema claro se aplica completo.
  • No quedan zonas mezcladas con estilos oscuros.
  • El estado se muestra como Guardado por perfil.
CU-ADM-27

Persistencia de apariencia por perfil

Pasos

  1. Cambiar tema con usuario A.
  2. Cerrar sesión e iniciar de nuevo con usuario A.
  3. Entrar con usuario B.

Resultado esperado

  • Usuario A conserva su preferencia.
  • Usuario B conserva la suya propia.
  • No se guarda como configuración global para todos.
CU-ADM-28

Bitácora de cambios administrativos

Pasos

  1. Crear invitación, cambiar rol o cerrar sesión remota.
  2. Abrir Bitácora.
  3. Buscar el movimiento.

Resultado esperado

  • La acción aparece con usuario responsable.
  • El detalle es entendible.
  • La fecha/hora coincide con la acción.
CU-ADM-29

Recarga, doble clic y errores

Pasos

  1. Guardar cambios administrativos y recargar.
  2. Probar doble clic en botones de guardar.
  3. Simular conexión lenta si es posible.

Resultado esperado

  • Los cambios persisten.
  • No duplica invitaciones, roles o acciones.
  • Los errores muestran aviso sin dejar datos a medias.
CU-ADM-30

Responsive y legibilidad

Pasos

  1. Probar escritorio, tablet y celular.
  2. Abrir modales de invitación, roles y seguridad.
  3. Revisar usuarios con correos largos o muchos roles.

Resultado esperado

  • Los elementos no se enciman.
  • Los botones siguen accesibles.
  • Los textos largos se acomodan sin romper tarjetas o tablas.
